This page demonstrates how encryption and decryption work, then explores how small key spaces make recovery attacks practical. The elliptic-curve example uses the same y² = x³ + 7 (mod 17) toy curve from Homework 1, Part 1—not the real secp256k1 parameters.

Educational warning: the curve has only 18 points in total and the selected base point has order 9. It is deliberately insecure and must never be used to protect real data.

Decryption

Use the private key to calculate M = C₂ − dC₁. Since dC₁ = d(rG) = r(dG) = rQ, the masking point cancels.

How text is represented: ASCII codes are written as three octal digits. Each digit 0–7 is mapped to point (digit + 1)G, so the toy group can represent it. This is an intentionally inefficient teaching encoding, not a standard message encoding.

DISCUSSION — 04

What do the experiments show?

Security depends on the algorithm, key space, message representation, and assumptions—not simply on whether a result looks random.

PropertyToy ECC ElGamalCaesar cipher
Key modelPrivate scalar d; public point Q = dGShared integer shift from 0 to 25
EncryptionUses a fresh ephemeral scalar and elliptic-curve point operationsMoves each letter by the same number of alphabet positions
DecryptionUses the private scalar to cancel the shared masking pointShifts letters back by the same key
Key-space attackFeasible here because only 8 nonzero scalar candidates are usedTrivial: test all 26 keys
StatisticsPoint arithmetic is not a hash function and does not imply an avalanche effect; tiny group outputs repeatLetter frequencies are preserved up to relabeling, enabling language-based attacks
Real-world statusDemonstration only; real ECC requires standardized parameters, large keys, secure encoding, and secure implementationInsecure and unsuitable for protecting information

Why Caesar frequency analysis works

Natural languages do not use letters equally often. A short ciphertext may be ambiguous, but longer samples reveal a more stable distribution. Exhaustive search always produces all 26 candidates; frequency scoring only ranks them and can be wrong for short text, unusual vocabulary, names, or non-English text.

Why ECC brute force is different

The ECC attack checks candidate private scalars against a known public key. It succeeds here because the allowed range is artificially tiny. For correctly generated ECC keys, exhaustive search is infeasible with realistic computing resources. This does not mean every ECC-based toy design is secure: small groups, poor randomness, unsafe encodings, and implementation flaws create additional weaknesses.
